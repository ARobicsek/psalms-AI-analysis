Three fixes: `_lift_following_translation` pulls a prose translation into the block (narrow by design — fires on **12 spans over 26 guides, all genuine**); `_render_quote_block` sets the translation **UPRIGHT against the italic original** with a 6pt seam gap inserted whether or not the writer marked it; and **` / ` renders as a real line break** — the writer already lineates with slashes from the dossier and **24 quote lines carried the mark**, printing literal slashes mid-verse. Guarded: 23 of 24 are verse, the exception being Ps 43's chiasm DIAGRAM, which its `**` bold markers identify.

- **THE LINE BREAKS WERE RECOVERABLE FROM THE DOSSIER.** Ps 1's translations had no slashes, but the echoes dossier lineates everything it supplies and held all three poems at **4 lines each**. The writer had flattened *and* reworded them ("granted"→"gave"), so `scripts/lineate_poem_translations.py` aligns token streams with difflib: a break in an EQUAL run carries its offset, a break in a **rewritten** span goes to the START of the rewrite (a first attempt with `get_matching_blocks` put Borges's break after "gave"). **Every insertion is round-tripped** — stripping the marks must reproduce the guide character for character — so it can reflow a translation but never alter a word, and **breaks come from the dossier, never from a model**. Ps 1: 3 translations, 4 lines against 4-line originals; corpus-wide it correctly touches nothing else. `RULE 12` gained a `HOW TO SET A QUOTED POEM` spec so this stays a backfill.
