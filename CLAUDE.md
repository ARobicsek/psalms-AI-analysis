**Session 369 (2026-07-27)**: Phonetic analyst rewrite — 16 bugs; stress placement 96.85% → 99.54% ($0, deterministic)
- **Trigger**: author read the Ps 70 Opus-5 guide and flagged two transcriptions as stressed on the wrong syllable — `yā-shū-**VŪ**` and `**YĀ**-siy-sū`. Both wrong; both penultimate: `yā-**SHŪ**-vū`, `yā-**SIY**-sū`. Ear was calibrated — the other three forms in the same sentence were right. **Not a model error**: `phonetic_analyst.py` is deterministic, its output lands in `micro_v2.json` and the writer quoted it faithfully.
- **One false premise, two failure modes.** The module assumed *accent glyph position = stressed syllable*. Ps 70:4 carries only **dehi** (prepositive — always on the first letter), which the old table excluded, so it fell to the "default = ultima" branch; but hollow-verb imperfect plurals are penultimate (all 10 other יָשׁוּבוּ occurrences accent the shin). Ps 70:5 carries **U+0598 + mahpakh**: Unicode names U+0598 "ZARQA" and the table believed it, rating it 2 against mahpakh's 1 so `max()` let it win. **Self-inconsistency proof**: the same word at Job 3:22 (revia) already transcribed correctly.
- **Accents reclassified from measurement, not names** (ground truth = stressed letter of a pointed form from occurrences with one unambiguous accent, ~192K words). This overturned two the old table had **backwards**: **geresh muqdam (8.8%)** and **ole (7.0%)** were rated reliable but are prepositive. **Six marks were missing from the table entirely** and fell through silently (segolta, qarney para, atnah hafukh, merkha kefula, dehi, zinor). Biggest single error source: **U+05BD rated a primary accent** — in **4,313** words it is a meteg away from the stress and outranked the real accent (only 48 coincide); it is now the stress only as the verse-final silluq. **U+0598's 49% was a bimodal mixture** — the prose zarqa (with a zinor partner, marks the stress) vs the poetic tsinnorit (with mahpakh/merkha, marks nothing); ranking it below the reliable accents resolves both. **Doubled accents**: `>=` let the later mark win, so a doubled pashta always took the edge copy — guaranteed wrong, since the doubling exists *because* the stress is not final; now the inner copy (segolta 100%, pashta 99.8%, telisha qetana 98.5%).
- **Stress lexicon** (`src/agents/stress_lexicon.json.gz`, 48,721 entries, 0.29 MB, built by `scripts/build_stress_lexicon.py`): where the accents give no position, the stressed letter is read from a verse where that form *is* unambiguously accented. Consulted **only** then, so it can never override a real accent; stores **letter** indices so it survives syllabifier changes; drops the 122 forms whose readings disagree (<60%) as genuine pausal retraction. **Hold-out** (built from non-Psalms books only, scored on Psalms): **125 fixes, 1 regression** — the in-sample 99.99% is partly circular and should not be quoted.
- **Eleven more bugs found while working.** Phantom final syllables from hiriq/tsere/segol+yod not being a mater (`'e-lō-hiy-**M**`), word-final consonant clusters (`rō'-sh`), voiced word-final shewas (`lə-hith-hal-lē-**KHƏ**`) and geminated mappiq (`hal-lū-yāh-h`). **`is_geminated` for begadkefat was dead code** — the guard tested `chars[k] in consonant_map` right after the loop broke on a *vowel* — hence `'a-tāh`, `sha-bāth`, `su-kāh`. **`_is_vocal_shewa` rule order** made its dagesh-forte rule unreachable (`tid-**FEN**-nū`), and the "second of two shewas is vocal" rule was missing (`wə-yis-**MḤŪ**`). Any vav+dagesh read as shureq, collapsing doubled waw (`ḥa-ūh` for חַוָּה, 823×). `{פ}` markers transcribed as a phantom `**F**`; paseq `׀` produced empty words — those were the stray double spaces in Ps 70. Plus: furtive patah can never take the ultima default; maqqef compounds ending in a stray maqqef got no stress; the `__main__` demo had a Latin `l` inside לְעוֹlָם and unaccented text, so it exercised nothing.
- **Results**: stress **96.85% → 99.54%** (5,173 errors removed), **30.4%** of all word transcriptions changed (4,436 in Psalms), **0 exceptions** over 262,799 words. Psalms provenance now `accent` 90.5% + `lexicon` 8.0% + `doubled` 0.1% = **98.6% read off the MT**, 1.4% still guessed. New `stress_source` field per word so an inferred stress is never mistaken for a Masoretic one. **The residual 0.5% on the accent path is mostly not error** — Gen 1:5 קָ֣רָא etc. are contextual retraction, where the module correctly follows the local accent and majority-vote ground truth cannot.

Ps 70's two words remain wrong in the shipped markdown — author explicitly did not want that text patched. Tests: `tests/test_phonetic_analyst.py`, 30 assertions, one per bug class (the archived test had none).

**Session 366 (2026-07-19)**: Divine-names converter — prefixed אֵל and three sibling misses ($0, deterministic)
- **Trigger**: author read the Ps 68 output and suspected the converter was missing instances of אֵל. Confirmed: **7 unconverted `הָאֵל`** in the shipped DOCX, incl. the giveaway line `הָאֵל לָנוּ קֵל לְמוֹשָׁעוֹת` (Ps 68:21) converting one El and not the other. Corpus-wide: 44 prefixed-El misses across 17 psalm outputs (worst: 42, 68, 57, 69).
- **Root cause** (`src/utils/divine_names_modifier.py`): the El pattern required whitespace/punctuation *immediately* before אֵ, so any attached prefix letter killed the match. Elohim had a prefixed-forms rule (Pattern 2b) since forever; El never got the equivalent.
- **Four fixes**: (1) **prefixed El** — new `_PREFIX` allows up to two stacked prefix letters (ה/ו/ל/ב/כ/מ) that must themselves sit on a boundary, so יִשְׂרָאֵל/יוֹאֵל/מִיכָאֵל stay untouched; (2) **Shaddai boundary** — its class was `[\s\-־.,;:!?]` vs El's fuller one, so `שַׁדַּי)` never converted (1 live miss in Ps 68); both now share one `_BOUNDARY` constant; (3) **trailing cantillation** on the final letter blocked the boundary lookahead (`אֶל־אֵל֮` Ps 43:4, `גַּם־אֵל֮` Ps 52:7); (4) **two-letter prefixes** (`וְלָאֵל` Ps 53). Fixes 3–4 found while verifying 1–2, same defect family.
- **Demonstrative guard** (judgment call, flagged to author): the corpus A/B caught a real false positive the prefix fix would have introduced — Gen 19:25 `הֶעָרִים הָאֵל` = "those cities", the archaic plural demonstrative, not the name. In all biblical instances (Gen 19:8/25, Lev 18:27, Deut 4:42/7:22/19:11, 1 Chr 20:8) it follows a definite plural noun; guard requires that noun immediately before (else Hebrew quoted after English prose misreads). Heuristic on a genuinely ambiguous form — revisit if it ever suppresses a real name.
- **Verification**: 46-case suite (convert + must-preserve: אֵלַי, אֵלֵךְ, הָאֵלֶּה, angel names, שָׂדָֽי/שְׁדּי) all pass; archived `test_divine_names_shin_sin.py` green after fixing one stale expectation (it asserted `וְאֵל` stays unconverted — that *was* the bug); **corpus A/B of HEAD vs patched modifier over all 150 psalm finals: 37 changes, all genuine divine names**, demonstrative preserved.
- **Deferred by author**: **יָהּ** — no rule exists at all (4 occurrences in Ps 68, incl. `בְּיָהּ שְׁמוֹ` v.5). Design call, not a regex bug: convention would be קָהּ or י־ה, and הַלְלוּיָהּ needs its own answer.
- **Outputs NOT regenerated.** The modifier runs at DOCX-build time on the edited markdown (`document_generator.py:1589`), so re-rendering Ps 68 and the 16 other affected psalms costs **no AI spend** — just a doc rebuild. Not yet done.
